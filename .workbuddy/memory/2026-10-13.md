## node-cheat-engine：Lua 桥崩溃修复 + CE Lua API 补全

### 1. 修复 userdata 悬垂崩溃（真实 use-after-free）

**症状**：脚本里只要出现一次 `collectgarbage()`，`getAddressList()` 拿到的对象就**永久失效**，
后续任何属性/方法访问抛「self 不是本引擎的对象（收到 userdata）」。

**根因**（`src/lua/objects.ts`）：
- `handleOfObject` 是 `WeakMap<object, number>`，同一宿主对象**永远**返回同一个 handle
- 但 `__gc`（`closureGc`）无条件 `objects.delete(handle)`
- 同一对象可以有多个 userdata（如 `getAddressList()` 是全局单例），
  任意一个被 GC 回收后，其余**仍存活**的 userdata 全部指向空槽位
- 且删除是单向的，没有任何路径会加回来 → **永久损坏**

**修复**：改为引用计数
- 新增 `handleRefs: Map<number, number>`，`pushObject` 时 +1，`closureGc` 时 -1，
  归零才真正从 `objects` 摘除
- `handleOf` 增加校验：`objects.has(cached)` 为假时重新分配句柄
- `dispose()` 里一并 `handleRefs.clear()`

**定位方法（可复用）**：给 `dist/cjs/lua/objects.js` 的 `handleOf` / `readUserdata` / `closureGc`
三处插 `process._rawDebug` 日志，观察 `handle` 与 `objects.size` 的变化即可锁定。
注意：改 dist 会被 `tsc` 覆盖，验证完要 `npx tsc -p tsconfig.json` 重新生成。

### 2. 新增 15 个 CE Lua API（61 → 76）

**`src/lua/memory.ts`（新文件）**：保护属性解析 + 区域查询
- `allocateMemory(size [, prot='RWX'])` / `deAlloc(addr)`
- `getMemoryProtection` / `getMemoryProtectionInfo` / `setMemoryProtection` / `fullAccess`
- `getRegionSize` / `enumRegions([filterTable])`
- 保护属性接受 CE 名字（`'R'`/`'RWX'`/`'WCX'`/`'?G'`）与 Win32 数值（`0x40`）

**`src/lua/asm.ts`（新文件）**：汇编/反汇编绑定
- `assemble(instr [, addr [, arch]])` 写内存 / `assembleBytes` 只编码
- `disassemble(addr [, count])` / `disassembleBytes(bytes [, addr [, count]])`
- 架构自动跟随目标进程位数

**`src/lua/bridge.ts`**：`createState()` 里 `await ensureAsmBackend()` 预热。
**必须做**——Lua 的 C 闭包不能 await，而后端是异步 WASM 加载，不预热则
脚本第一次调 `assemble` 必撞「后端尚未初始化」。

## 提权助手 bug 修复（用户明确要求：**不会点任何 UAC**）

用户约束：**不进行任何 UAC 点击**。因此审计重点是"无人工介入"路径。

### 修复 1：同意闸门 fail-closed 缺口（核心）

**症状**：`askToElevate` 里 `await userQuestions.ask(...)` 是裸的，用户不回应就**抛未捕获异常**。

**关键认识**：用户不介入是**常态**而非异常 —— 关掉弹窗 / 点取消 / 会话超时 /
profile 没有可交互的 user-questions 前端 / `signal` 提前 abort / 抛非 Error 值，
每一种都会让 `ask` 抛错。后果是：异常穿透到工具层 → 真正的失败原因（"没拿到同意"）被吞，
且闸门从 fail-closed 退化成"抛错"这种不确定状态。

**修复**：两份实现都把 `ask` 包进 try/catch，任何异常一律 `approved: false`。
- `D:/Project/dsh-get-admin/lib/elevation.js`（权威实现）
- `D:/Project/dsh-cheat-engine/lib/elevation-impl.js`（回退实现）

**必须两边同时改** —— 否则"回退路径"会变成绕过闸门的暗门。

### 修复 2：`launchTimeoutMs` 配置项根本不存在

`ce_elevation action=request` 传 `launchTimeoutMs`，但 `CONFIG_DEFAULTS` 里**从没定义过这个键**，
于是恒为 `undefined`，启动器套用提权默认的 **90 秒**。用户不点 UAC 就干等 90 秒。
已在 `lib/index.js` 补上该配置项，默认 30_000。

### 修复 3：无人值守闸门前置

`GET_ADMIN_NO_ELEVATE=1` 的硬闸门原本在 `launch.js` 的 spawn **之前**检查，
但流程已经先走完「征求同意 → 用户点同意 → 才被拒」。对于明确不点 UAC 的用户，
等于"先弹一次窗再拒绝"。现在 `ce_elevation action=request` 在**弹窗之前**就拒绝
（0ms、`ask` 完全不被调用），`status` 也显示 UAC 策略。

### 修复 4：建议文案自相矛盾

UAC 被禁用时 `permissionDeniedAdvice` 仍在推荐"会弹一次 UAC"的做法 ——
推荐一条必然被拒的路比不推荐更糟。两份实现都加了分支：禁用时只给不需要 UAC 的做法。

### 测试

`test/elevation-source.test.mjs`：7 → **12** 个用例。
踩坑：`GET_ADMIN_NO_ELEVATE` 是**进程级**环境变量，用例之间会互相污染 ——
必须显式设置并在 finally 恢复，否则后跑的用例会看到前一个留下的值。
