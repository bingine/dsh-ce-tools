能力边界

诚实的边界：请读完再用

本插件复刻的是 Cheat Engine 未加载内核驱动时的用户态能力。 做不到的事写在这里，而不是等你在半路撞上。

做不到

    会静默坑人

      指令里的裸数字按十进制解析

      mov eax, 1337 是十进制 1337。十六进制必须写 0x 前缀或 h 后缀。 这与 CE 帮助文档一致，但和「AutoAssembler 里什么都当十六进制」的直觉相反 —— 写错不会报错，只会静默产生错误的字节。

      所以本插件不靠「记文档」来防这个坑：ce_assemble 与 ce_auto_assemble 会把汇编结果反汇编回来一并展示：

      你写的 mov eax, 11223344
      实际编码 B8 30 41 AB 00
      反汇编核对 mov eax, 0xab4130

      立即数被解成什么值一眼可见 —— 想写十六进制就得写 0x11223344。

      配置

      从加载行的 config 读取

      未给出的键一律用出厂默认。只做分析时建议把 allowWrite 设为 false。 

      - insert:
    - id: cheat-engine
      name: 'dsh-ce-tools'          # 必须是包名，不是仓库目录名
      config:
        allowWrite: false          # 只读：禁掉 ce_write 与 AA 写入段
        backend: self              # self | native-ce（连 ceserver）
        kernelPath: 'D:/.../node-cheat-engine'
        pointerScanMaxLevel: 5
        pointerScanMaxOffset: 2048
        arch: ''                   # 空 = 按目标位数推断
        scanParallel: true
        maxReadBytes: 4096
        idleTimeoutMs: 1800000     # 空闲 30 分钟回收会话
      • allowWrite —— 默认 true。这是 CE 能力的核心，但也意味着模型可修改任意已打开进程的内存。
      • backend —— self 零依赖；native-ce 连官方 ceserver（需自行准备并启动）。
      • scanParallel —— 扫描分块并行，对扫描耗时影响明显。
